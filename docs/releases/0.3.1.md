# FerrisSearch 0.3.1

Release branch: `release/0.3.1`

Comparison base: `v0.3.0..v0.3.1`

FerrisSearch 0.3.1 fixes coordination, recovery, and query-admission issues
found after 0.3.0 and adds bounded failover/rejoin qualification. This patch
does not introduce new public APIs or change on-disk, WAL, or protobuf formats.

## Fixes

- **Forwarded writes:** Single and bulk write responses now propagate index
  metadata-version watermarks so coordinators carry the required applied
  state into later requests.
- **Recovery and schema evolution:** Peer-recovery cleanup and shard reopen
  paths avoid lock/engine-ownership deadlocks. Read shards reopen with evolved
  mappings without retaining the old engine while replacement waits.
- **Query admission and failures:** Initial search and SQL memory estimates
  account for live document/row counts, reservation reconciliation errors
  propagate, and remote-store queries preserve structured shard-failure
  responses, including client errors.
- **Development reliability:** Follower startup and reactive-setting checks
  wait for their actual metadata/application boundaries. CI disables debug
  information and incremental compilation and prunes linked test executables
  before saving its cache.

These changes include the post-0.3.0 fixes in #192 through #196.

## Failover And Rejoin Qualification

A new three-node process regression combines lost update/delete replies,
concurrent conditional mutations, primary process loss, promotion, old-primary
rejoin, and a further replica restart after flush. It checks exact operation
receipts, document values/deletes, allocation/canonical identity, and durable
checkpoints with request durability and a minimum of two durable copies.

The harness can retain child logs and a phase/receipt oracle journal through
`FERRIS_RECOVERY_TEST_LOG_DIR`. The
[dated acceptance record](../recovery-acceptance-matrix.md#d10-process-qualification-evidence-october-18-2026)
documents the executed schedules, reproduction commands, and bounds.

## Maturity And Limits

FerrisSearch remains pre-1.0 and is not yet a production-safe drop-in
OpenSearch replacement. It exposes an OpenSearch-style REST API subset.

The new qualification covers process crash/restart with intact disks, not
power-loss durability, unrestricted divergent-history rollback, vector
snapshot recovery, encrypted transport, or asynchronous durability. It does
not establish a production operating envelope or an unbounded D10 proof.
